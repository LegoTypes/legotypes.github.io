Avahi mDNS Reflector

Makes Bonjour discovery work across VLANs: AirPlay, AirPrint, HomeKit, Matter and every other mDNS/DNS-SD service a device announces on one network become visible on the others you choose.

Why this plugin

mDNS is link-local: an announcement on one VLAN never reaches another, so the moment printers, speakers or smart-home hubs live on their own network, the devices that should find them cannot. OPNsense's os-mdns-repeater copies raw packets between interfaces, which covers simple announcements but not everything. This plugin runs avahi-daemon in reflector mode instead: it answers and forwards full mDNS queries, including A/AAAA hostname records and DNS-SD service browsing, so both "find the printer" and "resolve printer.local" work across segments.

Using it

After installing, open Services > Avahi mDNS Reflector:

  • Enable, and pick the Interfaces to reflect between (at least two). The avahi-app package comes in automatically as a dependency.
  • Use IPv4 / Use IPv6: which families to handle. Reflect across IP versions is rarely needed.
  • Reflect Filters (optional): forward only the service types listed, for example _airplay._tcp, _raop._tcp, _ipp._tcp, _hap._tcp, _matter._tcp. Substring matching, so the .local suffix is not needed. Empty reflects everything.
  • Domain Name stays local unless you know otherwise.

A dashboard widget shows the daemon's state, and its log is under the same menu.

Firewall rules you need

The reflector only handles discovery. Two kinds of rule are still yours to add:

  • mDNS to the firewall on every selected interface: UDP port 5353 to 224.0.0.251 (IPv4) and ff02::fb (IPv6). An IGMP pass rule is recommended so the firewall can join the IPv4 group. Without these, the reflector hears nothing on that interface.
  • The services themselves: clients still connect by unicast to the device across VLANs, so allow the ports the service uses between the client and device networks, for example AirPlay (TCP 7000, 7100), AirPrint/IPP (TCP 631), HomeKit (TCP 51827).

Reliability

avahi-daemon's reflector has a fixed pool of 100 slots for legacy unicast reflection. Bursts of mDNS traffic can exhaust it, after which reflected services look offline for hours until the daemon restarts. The plugin ships a health check that finds the slot errors in avahi's log (avahi logs to its own file) and exits non-zero when it does. It reports; it does not restart anything by itself. To recover automatically, add it in Services > Monit as a Custom service with start and stop commands configctl avahireflector start and configctl avahireflector stop and a non-zero-status test whose action is restart. It is also the plugin's configd healthcheck action, for other monitoring; configctl avahireflector restart clears the condition by hand.

Limits

  • Conflicts with os-mdns-repeater: use one or the other.
  • Not CARP-aware: on an HA pair both nodes run the reflector.
